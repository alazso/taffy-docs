title: taffy-metrics
description: bStats and FastStats charts from one definition, with the plugin's handled errors sent from ErrorReports to FastStats error tracking.
---

`taffy-metrics` starts bStats and FastStats for a plugin from one set of chart definitions. A chart is declared once as a `MetricChart` and reported to every provider that starts. When FastStats starts, the plugin's handled errors, reported through the `ErrorReports` sink from [taffy-platform](/docs/modules/platform), go to FastStats error tracking under their source.

A plugin names three types from the module: `MetricChart`, `MetricsBuilder` and `Metrics`, all in `so.alaz.taffy.metrics`. No public signature names a bStats or FastStats type, so plugin code never imports either SDK.

| Type | What it is |
|---|---|
| `MetricChart` | One custom metric: a string, number, bool, string list or counter chart. |
| `MetricsBuilder` | Takes the owner plugin, its `ErrorReports` and the owner's switch, then the bStats service id, the FastStats token and the charts, and starts once. |
| `Metrics` | The live handle: diagnostics readers, `report`, from `0.2.1` `reportUnhandled`, and `shutdown` for disable. |

## Setup

The module is `so.alaz.taffy:taffy-metrics`, `alaz.taffy.metrics` in the catalog. It depends on `taffy-platform` as an API dependency, and publishes `org.bstats:bstats-bukkit` and `dev.faststats.metrics:bukkit` as runtime dependencies: a plugin compiles without them and its shadow jar carries them.

```kotlin title="build.gradle.kts"
plugins {
    id("so.alaz.taffy.paper-plugin")
}

dependencies {
    compileOnly(alaz.paper.api)
    implementation(alaz.taffy.metrics)
}
```

### Repository

The FastStats SDK resolves from `https://repo.faststats.dev/releases`. `so.alaz.taffy.settings` applies `so.alaz.taffy.repositories`, which already declares it (as the repository named `faststats`). A build that does not apply those settings plugins adds it itself:

```kotlin title="settings.gradle.kts"
dependencyResolutionManagement {
    repositories {
        mavenCentral()
        maven("https://repo.papermc.io/repository/maven-public/")
        maven("https://repo.alaz.so/releases")
        maven("https://repo.faststats.dev/releases")
    }
}
```

### Relocation

Each plugin carries its own relocated copy of both SDKs and of Taffy. `so.alaz.taffy.paper-plugin` handles this: its `shadowJar` relocates `org.bstats`, `dev.faststats` and `so.alaz.taffy` to `<group>.libs.bstats`, `<group>.libs.faststats` and `<group>.libs.taffy`, and its duplicates strategy keeps one `META-INF/faststats.properties`.

A build on another shadow setup relocates the same three packages and keeps that file in the jar:

```kotlin title="build.gradle.kts"
tasks.shadowJar {
    relocate("org.bstats", "com.example.myplugin.libs.bstats") {
        include("org.bstats.**")
    }
    relocate("dev.faststats", "com.example.myplugin.libs.faststats") {
        include("dev.faststats.**")
    }
    relocate("so.alaz.taffy", "com.example.myplugin.libs.taffy") {
        include("so.alaz.taffy.**")
    }
}
```

Each `include` keeps a relocation inside its package: without one, Shadow matches the raw path prefix, so `relocate("so.alaz.taffy", ...)` also moves a package named `so.alaz.taffyshop`. From `0.4.1`, `so.alaz.taffy.paper-plugin` sets the same three includes.

<Callout type="warn" title="Both are required">
bStats refuses to start from classes that were not relocated. FastStats cannot create its context without `META-INF/faststats.properties`; without the file, `start()` logs one warning and leaves FastStats off before it writes `plugins/faststats/config.properties`.
</Callout>

Neither SDK may be listed as a Paper runtime library (`paperPlugin.runtimeLibrary(...)`), which would load it unrelocated.

## Starting metrics

In `onEnable`, a plugin:

<Steps>
<Step>
Reads its metrics switch from its own config.
</Step>
<Step>
Creates a `MetricsBuilder` with itself, its `ErrorReports` and the switch, and gives it its bStats service id and FastStats token. An unset id or token leaves that provider off.
</Step>
<Step>
Adds its charts. A chart's supplier reads in-memory state only.
</Step>
<Step>
Calls `start()` as the last step of enable, once the state the charts read exists, and keeps the returned `Metrics`.
</Step>
</Steps>

```java title="MyPlugin.java"
import org.bukkit.plugin.java.JavaPlugin;
import so.alaz.taffy.config.ConfigHolder;
import so.alaz.taffy.config.ConfigLoadException;
import so.alaz.taffy.config.ConfigLoader;
import so.alaz.taffy.config.ConfigReader;
import so.alaz.taffy.metrics.MetricChart;
import so.alaz.taffy.metrics.Metrics;
import so.alaz.taffy.metrics.MetricsBuilder;
import so.alaz.taffy.platform.ErrorReports;
import so.alaz.taffy.platform.Shutdown;

import java.util.concurrent.atomic.LongAdder;

public final class MyPlugin extends JavaPlugin {

    private static final int BSTATS_SERVICE_ID = 12345;
    private static final String FASTSTATS_TOKEN = "0123456789abcdef0123456789abcdef";

    private final ErrorReports errors = new ErrorReports();
    private final LongAdder commandsRun = new LongAdder();
    private volatile String storageType = "sqlite";
    private ConfigHolder<Settings> settings;
    private Metrics metrics;

    record Settings(boolean metrics) {
    }

    @Override
    public void onEnable() {
        ConfigLoader files = new ConfigLoader(
            getDataPath(), () -> getResource(ConfigLoader.FILE_NAME), getLogger());
        try {
            settings = ConfigHolder.load(
                () -> new Settings(new ConfigReader(files.load(), getLogger()::warning).bool("metrics", true)),
                getLogger()::warning);
        } catch (ConfigLoadException failure) {
            getLogger().severe("The settings could not be loaded: " + failure.getMessage());
            getServer().getPluginManager().disablePlugin(this);
            return;
        }
        boolean metricsOn = settings.startup().metrics();
        MetricsBuilder builder = new MetricsBuilder(this, errors, metricsOn)
            .bStats(BSTATS_SERVICE_ID)
            .fastStats(FASTSTATS_TOKEN);
        if (!startStorage()) {
            metrics = builder.start();
            getServer().getPluginManager().disablePlugin(this);
            return;
        }
        metrics = builder
            .addChart(MetricChart.string("storage_type", () -> storageType))
            .addChart(MetricChart.counter("commands_run", commandsRun::sum))
            .start();
    }

    @Override
    public void onDisable() {
        if (metrics != null) {
            Shutdown.closeQuietly("shut down metrics", metrics::shutdown, getLogger(), errors);
        }
    }

    private boolean startStorage() {
        return true;
    }
}
```

The switch is a component of the settings record a `ConfigHolder` of [taffy-config](/docs/modules/config) keeps, and it is read from `startup()`, because metrics start once per enable. A plugin reads it there and not through `getConfig()`, which no reload of the holder refreshes ([Moving a plugin off getConfig()](/docs/modules/config#moving-a-plugin-off-getconfig)). An enable whose settings do not load has no switch to read, so it starts no metrics.

An enable that gives up after the switch is read, such as when storage fails to start, still calls `start()` before it returns, without the charts whose state never came up. Its disable then shuts the metrics down, and the reports raised during enable go out in the final send. Without that call they are lost.

### MetricsBuilder

| Member | Behaviour |
|---|---|
| `MetricsBuilder(Plugin owner, ErrorReports errors, boolean enabled)` | The owner's logger receives the start warnings. `enabled` is the owner's switch: `false` starts nothing. A null owner or sink throws `NullPointerException`. |
| `bStats(int serviceId)` | Reports to bStats under the plugin's service id. A value of 0 or below leaves bStats off. |
| `fastStats(@Nullable String token)` | Reports to FastStats under the plugin's project token, with error tracking on. A `null` or blank token leaves FastStats off. |
| `addChart(MetricChart chart)` | Adds a chart for every provider that starts. A second chart with the same id throws `IllegalArgumentException`; a null chart throws `NullPointerException`. |
| `usageChart(boolean enabled)` | From `0.2.1`. `false` leaves [the Taffy usage chart](#the-taffy-usage-chart) off while the plugin's own metrics start as before. It is on when this is not called. |
| `start()` | Starts every provider whose credential is set, when the switch is on, and returns the handle. Never returns `null`. |

Every setter returns the builder. A builder starts once: after `start()`, every call on it, a second `start()` included, throws `IllegalStateException` (except `addChart(null)`, which throws `NullPointerException` first). The builder is not thread-safe; build and start it on one thread.

With the switch off, `start()` touches no metrics SDK, clears the error sink and returns an inert `Metrics`.

### FastStats token rules

A token that does not match `[a-z0-9]{32}` (32 lowercase letters and digits), such as a placeholder, is refused at `start()` and logged as one warning, before FastStats reads or writes any file. A jar without `META-INF/faststats.properties` is refused the same way. A refused start leaves the server's first run to the next plugin that starts FastStats.

On the first start of a server with no `plugins/faststats/config.properties`, FastStats writes the file, prints its own first-run notice of several lines through the plugin's logger, and sends nothing until the next start.

### Failure handling

A provider that fails to start is logged as one warning through the owner's logger (`bStats metrics failed to start: ...` or `FastStats metrics failed to start: ...`) and skipped, and enable goes on. A FastStats start that fails after its context exists shuts the context down with submission turned off, so it sends nothing. Taffy logs nothing else. FastStats with its `debug` option on logs each send through the plugin's logger.

## Charts

Each `MetricChart` factory takes an id and a supplier, and maps to one chart on each provider:

| Factory | Supplier | bStats | FastStats |
|---|---|---|---|
| `MetricChart.string(String id, Supplier<@Nullable String>)` | One string | `SimplePie` | string metric |
| `MetricChart.number(String id, Supplier<@Nullable Integer>)` | One integer, reported as is | `SingleLineChart` | number metric |
| `MetricChart.bool(String id, Supplier<@Nullable Boolean>)` | One boolean | `SimplePie` of `true` or `false` | bool metric |
| `MetricChart.stringList(String id, Supplier<List<String>>)` | A list of strings | `AdvancedPie` of how often each string occurs | string array metric |
| `MetricChart.counter(String id, LongSupplier total)` | A running total that is never reset | `SingleLineChart` of the increase | number metric of the increase |

```java
import so.alaz.taffy.metrics.MetricChart;

import java.util.List;
import java.util.Set;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.atomic.LongAdder;

final class Charts {

    private final AtomicInteger openMenus = new AtomicInteger();
    private final Set<String> hooks = ConcurrentHashMap.newKeySet();
    private final LongAdder tradesCompleted = new LongAdder();
    private volatile boolean webhookOn;
    private volatile String language = "en";

    List<MetricChart> all() {
        return List.of(
            MetricChart.string("language", () -> language),
            MetricChart.number("open_menus", openMenus::get),
            MetricChart.bool("discord_webhook", () -> webhookOn),
            MetricChart.stringList("hooks", () -> List.copyOf(hooks)),
            MetricChart.counter("trades_completed", tradesCompleted::sum));
    }
}
```

A null value from a string, number or bool supplier leaves that value out of the report. bStats also leaves out an empty string and a number of 0. A string list supplier returns an empty list, never `null`, when there is nothing to report.

### Counters

A counter reads one monotonically increasing total, such as `LongAdder::sum`. Each provider keeps its own mark and reports the increase since that mark, so the charts show activity per interval and no event is split between the providers. A total that goes down reports 0 for that interval, and the next interval counts from the lower total.

On bStats the mark advances when bStats reads the chart, and an increase above `Integer.MAX_VALUE` is reported as `Integer.MAX_VALUE`. bStats gives no sign of a submission that failed, so the increase read for it is lost. On FastStats the mark advances only after a submission is accepted, so a failed submission, or a read made while FastStats assembles an error report, leaves the count for the next report. A submission that arrived without FastStats seeing it accepted is counted again in the next one.

### Ids

Every id matches `^[a-z0-9_]+$` and is not one of the ids FastStats fills itself in every report: `client`, `core_count`, `java_vendor`, `java_version`, `os_arch`, `os_name`, `os_version`, `game_version`, `online_mode`, `player_count`, `plugin_version`, `server_type` and `platform_version`. A factory given another id throws `IllegalArgumentException` when the chart is declared, and a null id or supplier throws `NullPointerException`.

### What a chart may report

<Callout type="warn" title="Chart values leave the server unchanged">
A chart's id and every value its supplier returns are sent as they are: the [anonymize rules](#anonymizing) apply to error reports only. A value is a constant of the plugin or a category from its configuration, such as a storage type or a language code, and never a player name, a UUID, an address, a world name or a server name.
</Callout>

### The supplier contract

<Callout type="info" title="Suppliers read memory only">
A supplier only reads in-memory state. It never resets what it reads, never blocks and never touches storage.
</Callout>

- A supplier may run on any thread. bStats reads it on the server's main thread (its own thread on Folia). FastStats reads it on its asynchronous submission task, again whenever it assembles an error report, and once more during the final send at disable, on the thread of that send (from `0.2.1`, the `taffy-metrics-final-send` thread), which may come after the plugin's storage has closed.
- A supplier that throws makes that value absent from that report. On FastStats the throwable is also reported to the plugin's global error tracker, when FastStats error tracking is on, on every read that throws.

## The Metrics handle

`start()` returns a `Metrics` that wraps the providers that started. Keep it for the life of the plugin and call `shutdown()` on disable.

Metrics start once per enable and are not restarted on a config reload. `shutdown()` does not unregister the `ServerExceptionEvent` listeners FastStats registered for the plugin, which stay registered until the plugin is disabled, so each further start in the same enable adds to them.

### Diagnostics

The state readers report what each provider is actually doing, for a plugin's diagnostics command. They read cached state without blocking and never throw, so they are safe on any thread. On an inert handle and after `shutdown()` they read `false` or `null`.

| Reader | Reads |
|---|---|
| `bStatsStarted()` | `true` while bStats runs. `false` when the server owner turned bStats off in `plugins/bStats/config.yml`. |
| `fastStatsSdk()` | The FastStats SDK name and version, such as `bukkit 0.32.2`, or `null` when FastStats did not start. |
| `fastStatsEnabled()` | `true` while FastStats runs and is enabled for this server. |
| `fastStatsSubmitting()` | `true` while FastStats submits metrics. |
| `fastStatsCharts()` | `true` while FastStats submits the plugin's charts, which needs `submitAdditionalMetrics` on. |
| `fastStatsErrorTracking()` | `true` while FastStats submits error reports, which answers whether a report handed to `report` will be sent. |

```java
import so.alaz.taffy.metrics.Metrics;

import java.util.List;

final class MetricsStatus {

    static List<String> lines(Metrics metrics) {
        String sdk = metrics.fastStatsSdk();
        return List.of(
            "bStats: " + (metrics.bStatsStarted() ? "running" : "off"),
            "FastStats: " + (sdk == null ? "off" : sdk),
            "FastStats enabled: " + metrics.fastStatsEnabled(),
            "FastStats metrics: " + metrics.fastStatsSubmitting(),
            "FastStats charts: " + metrics.fastStatsCharts(),
            "FastStats errors: " + metrics.fastStatsErrorTracking());
    }
}
```

`fastStatsErrorTracking()` cannot see the Error Tracking switch in the project's settings on the FastStats dashboard, which discards reports when off. It does not see the error sink either: after the plugin installs a target of its own that does not pass reports to `report`, a report made through the sink is not sent, and the reader still reads `true`.

### Shutdown

`shutdown()` is the last step of disable, after the plugin's other shutdown steps, `DiscordWebhook.close()` included. In order, it clears the error sink, stops the Taffy usage chart without a final send, stops bStats, and has FastStats send its last errors and metrics and stop. A step that fails does not stop the next. It is idempotent and never throws. Because it runs last, the reports raised by the earlier shutdown steps go out in that final send.

<Callout type="info" title="The final send holds the disabling thread for 5 seconds at most">
From `0.2.1`, the final send runs on a daemon thread named `taffy-metrics-final-send`, and `shutdown()` waits at most 5 seconds for it, holding no lock. A send that finishes sooner ends the wait. The send makes one request for errors and one for metrics. Each has 3 second connect and request timeouts, which do not cover a stalled name lookup or a response that never finishes. When the 5 seconds pass first, `shutdown()` returns and the send goes on, on that thread, until it finishes or the JVM exits, which can be after the plugin's class loader was closed. An interrupt, also one already set on the calling thread when `shutdown()` is called, ends the wait at once and stays set.

Through `0.2.0` the send ran on the calling thread with no limit, so on a stalled network `shutdown()` could block the disabling thread for tens of seconds.
</Callout>

## Error tracking

Plugin code reports handled errors through its `ErrorReports` and never calls FastStats itself:

```java
try {
    loadShop();
} catch (IOException ex) {
    errors.report("shop.load", ex);
}
```

The source key is sent unchanged as the `source` attribute of the error, and no anonymize rule applies to it. It is a constant of the plugin or a category from its configuration, and never holds a player name, a UUID, an address, a world name or a server name.

`ErrorReports` holds the reports raised before its first install or clear, the first of each source and at most 16. When FastStats starts with its error service, `start()` installs the handle into the sink: the held reports are delivered to FastStats error tracking on the calling thread, and every later report goes there too, each under its source. Otherwise `start()` clears the sink, which discards the held reports, and nothing receives later reports.

There is no error service when the switch is off, no token is set, FastStats fails to start, the server is on its first run, the server was started with `-Dfaststats.enabled=false`, or the server owner turned off `enabled` or `submitErrors` in `plugins/faststats/config.properties`.

### What FastStats receives

- **Handled reports.** Each report made through `ErrorReports.report`.
- **Unhandled reports.** Each kind of report made through `ErrorReports.reportUnhandled`, which is how `Scheduler` reports a task Paper's region, async or entity scheduler runs that throws (those schedulers fire no `ServerExceptionEvent`). From `0.2.1`, such a report is sent with `handled` set to `false`, as an exception FastStats catches itself is. Before, it was sent as a handled report.
- **Chart failures.** A chart supplier that throws, on every read that throws.
- **Paper's exception events.** Each exception Paper reports for the plugin in a `ServerExceptionEvent`, such as one thrown from one of its event handlers, sent without a source.

Reports of one kind from one source merge into one error with a count, and each error carries its source as the `source` attribute. Two reports are of one kind when their exception classes, stack frames and messages match through the whole cause chain, once the anonymize rules have hidden addresses, UUIDs and the like. From `0.2.1`, an IPv4 address, an IPv6 address and a run of digits in a message each count as the same whatever their value, so `timeout after 5003ms` and `timeout after 71ms` are one kind, sent with the message of the first report. Messages that differ in a name or other text are still separate kinds. A scheduled error submission runs every 30 minutes. Once the first report has arrived, every scheduled error submission and the final send post an `errors` array, even when it is empty.

| Limit | Value |
|---|---|
| Sources with a tracker of their own | The first 64. Reports from any further source are sent without a source, and those sources share one limit of kinds. |
| Kinds per source | 32 for the life of the handle. A report of any further kind from that source is dropped. From `0.2.1`, one warning that names the source is logged on the plugin's logger when the source holds its 32nd kind, and one for the sources past the first 64 together. A handle from a new `start()` starts with none. |
| Reports held before `start()` | 16, the first of each source. |

FastStats does not merge unhandled errors into one with a count. The first unhandled report of a kind from a source is therefore sent, and a later unhandled report of that kind from that source is not sent for the life of the handle: a repeating task that throws the same exception on every run is sent once. A handled report of the same kind is sent as a handled error beside it, with its count.

FastStats clears every report it holds once a scheduled error submission is accepted, so a report made while that send is in flight is lost. A later report of the same kind is sent as usual, with its count starting again. The final send in `shutdown()` has no such window, because the error sink is cleared before it.

### Anonymizing

Every FastStats error tracker of this module applies these rules to the messages of a report, in this order:

| | Hidden | Sent as |
|---|---|---|
| 1 | A whole jdbc URL, up to the next whitespace or quote. A jdbc URL whose third part is an absolute path, also behind `file:`, such as `jdbc:sqlite:C:\Users\John Smith\server\data.db` or `jdbc:sqlite:/home/john/My Server/data.db`, is read with the folder names of rule 12, spaces included. | `jdbc:[redacted]` |
| 2 | The user name and password before the `@` of a URI of any scheme, when both are present. The password runs to the last `@` before the next whitespace when that `@` is at most 128 characters in and no `://` comes before it, a `/` included, and otherwise to the last `@` before the next `/`. What follows the `:` is read as a port when it is 1 to 5 digits that end the text or that whitespace or one of `/ ? # [ ] { } "` follows, as in `http://localhost:8080/users/a@b` or `[redis://cache-1:6379]`, so a password of that shape stays. | `redis://[credentials hidden]@[host hidden]:6379` |
| 3 | An email address whose last label has two or more characters, with a `+` in the name before the `@`, as in `john+tag@example.org`. | `[email hidden]` |
| 4 | A bearer token, and the credentials after `Authorization: Basic` in either letter case and 1 to 4 spaces, also with a `=` or `,` for the `:`, a quote after the key, up to four spaces around that sign and up to two quotes or opening brackets before `Basic`, as in `{Authorization=[Basic dXNlcjpwYXNz]}` or `setHeader("Authorization", "Basic dXNlcjpwYXNz")`. One word of letters with no upper case letter after its first stays, so `Authorization: Basic authentication is not supported` reads as written. The word `Basic` anywhere else stays. | `Bearer [token hidden]` |
| 5 | An AWS access key id. | `[aws-key hidden]` |
| 6 | A UUID in either letter case, with its dashes, also inside a longer word such as `data_<uuid>`, or as 32 hex digits without them that no further hex digit touches. | `[uuid hidden]` |
| 7 | The quoted user and host of a MySQL or MariaDB account, as in `'mc_prod'@'db.example.net'`. | `[user hidden]@[host hidden]` |
| 8 | The double-quoted name after the word `user` or `role` in either letter case, as in PostgreSQL's `password authentication failed for user "mc_prod"`, when the name is 1 to 64 characters without whitespace. | `user [user hidden]` |
| 9 | An `api_key`, `apikey`, `token` or `secret` query value. | `?token=[redacted]` |
| 10 | The value after `=` or `:` of a key that holds `password`, `passwd`, `pwd`, `passphrase`, `secret`, `token`, `api_key`, `access_key`, `private_key`, `license_key` or `licence_key`, in either letter case and with `-` or nothing in place of the `_`, and the value after the `=` of a key that ends in `pass` with no letter before it, such as `pass=` or `db_pass=`, or in `Pass` after a lower case letter, such as `dbPass=`. Such a key in quotes is a key before a `:` too, as in `"db_pass": "x"`, and its value of 1 to 3 digits stays before either sign, so `pass=3 fail=2` reads as written. A `=>` counts as the `=`. The value is one word or a quoted text. It is the rest of the line when a key that ends in `password`, `passwd`, `pwd` or `passphrase` starts its line with up to 64 characters before that word, also after the `-` of a list item, and the value starts with no quote, as in `password: my pass word`. A value that starts with `-` and a space is a list: it is the rest of that line and every following line that starts with `-` and a space, also past blank lines and lines that hold only a `#` comment, so the items on the lines below `tokens:` are hidden as one value. The value `YES` or `NO` stays, so `(using password: YES)` reads as the driver wrote it. The plain word `token`, `tokens`, `secret` or `secrets` before a `:` is no key when a letter, a digit or a `_` and whitespace come before it, so `Invalid token: expected ;` stays. It is a key when it is quoted, when it starts its line, also after the `-` of a list item, after any other character and up to 8 spaces or tabs, as in `Loaded {token: abc}`, `login failed, token: abc` or `discord: token: abc`, and when its value has 6 or more characters with a digit among the first 65, as in `Bot token: abc123`. Such a word is a key before a `=`, and so is a longer name around it before either sign, such as `bot-token`, `discord.token`, `tokenValue` or `secretKey`. | `db_password=[redacted]` |
| 11 | An SQL statement that starts with `SELECT ... FROM`, `INSERT INTO` (also `INSERT IGNORE INTO` and `INSERT OR REPLACE INTO`), `UPDATE ... SET`, `DELETE FROM`, `REPLACE INTO`, `MERGE INTO`, `CREATE TABLE`, `ALTER TABLE` or `DROP TABLE` in either letter case, with what follows that start on the line, up to 200 characters. A `FROM` or `INTO` that `the`, `an`, `this`, `that`, `these`, `those`, `your`, `my`, `our` or `their` follows starts no statement, so `Could not delete from the cache` stays, when spaces and a letter come after that word and none of these stands in the 200 characters after it, on its line or a later one and before the next `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `REPLACE`, `MERGE`, `CREATE`, `ALTER` or `DROP`: `WHERE`, `VALUES (`, `DEFAULT VALUES`, `RETURNING`, `ORDER BY`, `GROUP BY`, `HAVING`, `LIMIT` and a digit, `SET` with a name and a `=`, `JOIN` or `USING` with `ON` at most three words later, `--` or `/*`. After `SELECT` this holds only when 1 to 8 words of letters stand between it and `FROM`, so `Please select a kit from the list` stays and `SELECT * FROM the list` is hidden. A statement whose table has one of the ten words as its name and that holds none of those, such as `SELECT name FROM the t`, stays as well. | `[sql hidden]` |
| 12 | A `file:` URL that no letter or digit precedes, up to the next whitespace or quote, and a Windows path that starts with a drive letter and a backslash, or with a drive letter that no letter or digit precedes and one `/`, with two backslashes, a server name of letters, digits, `_`, `.`, `$` and `-` and a backslash, as in `\\fileserver\share\John\x.yml`, or with `Users` in either letter case that no letter or digit precedes and a backslash, as in `..\Users\John\x.yml`, which is hidden from `Users` on. Each of the first 64 folder names of the path holds up to three single spaces, as in `C:\Users\John Smith\Desktop\x.yml`. A space ends the path when no `\` or `/` follows within three more words, and when the word before it ends in a file extension (a dot, a letter and up to four more letters or digits), so `C:\srv\x.yml is not valid/readable` keeps its words. A path without such an extension takes the words up to that slash with it, as in `C:\srv\data and logs/x`. | `[path hidden]` |
| 13 | An absolute Unix path of one segment and a further slash or more, such as `/home/` or `/home/mc/server/plugins`. `/home` alone stays. Each of the next 64 folder names holds up to three single spaces between words of letters, digits, `_`, `.` and `-`, as in `/home/john smith/server/x`, and a space ends the path as it does in rule 12. A space also ends it before the lower case word `to`, `at`, `in`, `is`, `on`, `from`, `after`, `with`, `uses`, `has`, `was` or `not`, so `Failed to save /srv/world after 3 attempts/retries` keeps the words after the path. | `[path hidden]` |
| 14 | The id and token of a Discord webhook URL that starts with `https://` or `http://` on `discord.com` or `discordapp.com`, also with a `canary` or `ptb` label or an API version, and its query. | `https://[host hidden]/api/webhooks/[id hidden]/[token hidden]` |
| 15 | A host name of two or more labels that ends in `com`, `net`, `org`, `io`, `gg`, `dev`, `me`, `co`, `xyz`, `eu`, `de`, `uk`, `us`, `fr`, `nl`, `ca`, `au`, `ru`, `br`, `pl`, `internal`, `local` or `lan`. A name whose first label is `java`, `javax`, `jdk`, `sun`, `kotlin`, `com`, `org` or `net` stays, such as `java.io` or `com.example.Me`, and so does a name of two labels of two letters each, such as `pt.br`. | `[host hidden]` |
| 16 | The double-quoted name after the word `database` in either letter case, as in PostgreSQL's `no pg_hba.conf entry for host "10.0.0.5", user "mc_prod", database "survival_prod"`, or the single-quoted one, as in the `Unknown database 'survival_prod'` of MySQL and MariaDB, when the name is 1 to 64 characters without whitespace. | `database [database hidden]` |
| 17 | The host after the `://` of a URI of any scheme, with any ending and also of one label, such as `cache` in `redis://cache:6379`, together with a user name before an `@`. The host `localhost` stays. | `redis://[host hidden]:6379` |
| 18 | A dotted name of two or more labels with any ending that follows `UnknownHostException:`, `connect to`, `connecting to`, `connection to`, `connected to`, `route to`, `host` or `host is known` in either letter case and one space, also behind an opening quote or parenthesis. The same holds after a key that ends in `host`, `hostname` or `address` and a `=` or `:`, also with a quote around the key, one space on either side of the sign and up to two opening quotes or brackets, as in `address=(host=db.myserver.host)`, `No route to host: db.myserver.host` or `"host":"db.myserver.host"`, after `refused:`, `timed out:` or `timed out after 30000 ms:` and one space, and after the `.` and space that end the `address=(host=...)(port=...)(type=...)` of a MariaDB driver message, which repeats the host there. A name stays when it starts with digits, a dot and a digit, such as `1.21.4`, when its last label starts with an upper case letter, such as `so.alaz.shop.Sync`, when a `(` follows it, such as `player.getName()`, and when its last label is `yml`, `yaml`, `json`, `properties`, `toml`, `conf`, `cfg`, `xml`, `txt`, `log`, `csv`, `sql`, `db`, `sqlite`, `dat`, `jar`, `class`, `java`, `lock`, `tmp` or `bak`, such as `config.yml`. | `Connection to [host hidden]:5432 refused` |
| 19 | A token that no letter, digit, `_` or `-` precedes and that starts with `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`, `xoxa-`, `xoxb-`, `xoxe-`, `xoxo-`, `xoxp-`, `xoxr-` or `xoxs-` and 8 or more further characters, or with `sk_live_` or `rk_live_` and 16 or more, and a JSON Web Token: two parts that each start with `eyJ` and a third part, which may be empty, with a `.` between them. | `[token hidden]` |

Outside a URI and the words of rule 18, a host name of one label, such as `cache` or `localhost`, stays as written, and so does a host name with another ending. A relative path stays unless it holds `Users` and a backslash, and so does a dotted name that a further label follows, such as the class name `org.apache.commons.io.FileUtils`. Any other dotted name whose last label is one of the endings of rule 15 is hidden, a file name, a class name and a configuration key included, such as `messages.de`, `me.john.Me` or `shop.me`. After the words of rule 18, any dotted name outside the four shapes that rule leaves is hidden, so `No value for host shop.balance` is sent as `No value for host [host hidden]`.

From `0.2.1`, rules 2, 7, 8, 10, 13 and 15 are new, rule 14 hides what the SDK's own Discord webhook rule hid before (the SDK applies its rules after these, when rule 15 has replaced the host name), rule 6 also hides a UUID in upper case or without dashes, and the jdbc rule runs first: before, a jdbc URL with a user name before an `@` kept its path and query behind the email placeholder. Reports whose messages differ only in a value these rules hide now merge into one kind.

From `0.2.1`, rule 11 needs the start of a statement. Before, it matched the bare words `select`, `insert`, `update` and `delete` and hid the rest of the line, so `Failed to update balance for shop 12: timeout after 5003ms` was sent as `Failed to [sql hidden]`. Such a message is now sent as written, and so is a statement of another shape, such as `SELECT 1`. A sentence that holds one of these starts, such as `Could not delete from disk cache`, is still hidden from that word on.

From `0.4.2`, rules 16, 17 and 18 are new, and rules 1, 2, 3 and 12 hide more. Before, rule 1 stopped at the first space, so `jdbc:sqlite:C:\Users\John Smith\server\data.db`, the shape `Storage` builds for SQLite, was sent as `jdbc:[redacted] Smith\server\data.db`. The database name of the `pg_hba.conf` message, the host of a URI such as `redis://cache:6379` or `https://db.myserver.host/v1`, and the name in `Connection to db.myserver.host refused`, `No route to host: db.myserver.host` or the MariaDB driver's `Socket fail to connect to address=(host=db.myserver.host)(port=3306)(type=primary). db.myserver.host` were sent as written. So was any other dotted name after the words of rule 18, such as `shop.balance` in `No value for host shop.balance`, which is now hidden.

From `0.4.2`, rule 2 reads a port that ends the text or that whitespace or one of `/ ? # [ ] { } "` follows as a port, and its password holds no `://`. These rules come on top of what the SDK hides by itself in every report: IPv4 and IPv6 addresses, the user name in a home directory path, the password in a jdbc URL, and the JVM's `user.name`. FastStats data is pseudonymous.

### Uncaught exceptions

Taffy leaves the JVM default uncaught exception handler alone: neither `MetricsBuilder.start()` nor `Metrics.shutdown()` installs, replaces or restores it. An uncaught exception on a thread the plugin starts itself is printed by the JVM as usual and is not sent to FastStats. A plugin that wants such an error tracked catches it and reports it through `ErrorReports`:

```java
Thread worker = new Thread(() -> {
    try {
        rebuildIndex();
    } catch (RuntimeException ex) {
        errors.report("index.rebuild", ex);
    }
}, "myplugin-index");
worker.start();
```

### The error sink has one target

Each `ErrorReports.install` replaces the target before it, and only the first install receives the held reports. A plugin using this module therefore installs no target of its own before `start()`: such a target would take the held reports, and `start()` would then replace it. A target installed after `start()` replaces the handle in turn, and FastStats receives no further report through the sink.

A plugin that also wants its reports elsewhere installs, after `start()`, one target that passes each report to `Metrics.report` or `Metrics.reportUnhandled` and to its own handler:

```java
metrics = builder.start();
errors.install((source, error) -> {
    metrics.report(source, error);
    getLogger().warning("Handled error in " + source + ": " + error);
}, (source, error) -> {
    metrics.reportUnhandled(source, error);
    getLogger().warning("Unhandled error in " + source + ": " + error);
});
```

`Metrics.report(String source, Throwable error)` and, from `0.2.1`, `Metrics.reportUnhandled(String source, Throwable error)` do nothing on a handle without a FastStats error service and after `shutdown()`, and never throw. A target installed with the one-handler `install` that passes every report to `Metrics.report` sends a `Scheduler` failure as a handled error, as before `0.2.1`.

`shutdown()` clears the sink, which holds nothing after its first install or clear: a plugin that restarts its metrics on reload with the same sink loses the reports raised between the shutdown and the next `start()`.

## The Taffy usage chart

With the switch on, `start()` also starts Taffy's own usage metrics on the same plugin, unless the plugin turned them off with `usageChart(false)` or another plugin on the server already reports them (see below):

- a second bStats instance under Taffy's bStats service id, 35379, when the plugin's own bStats instance started;
- a second FastStats context, with metrics only and no error tracking, under Taffy's FastStats token, when the plugin's own context started.

Each reports one chart, `taffy_version`, the Taffy version the plugin was built with, beside what the SDK sends for any plugin. Taffy therefore adds no provider, configuration file or first-run notice that the plugin's own metrics do not. The server owner's opt-outs in `plugins/bStats/config.yml` and `plugins/faststats/config.properties` apply to it as to the plugin's own metrics. At disable it stops before the plugin's own providers, without a final send. A failed start logs one warning (`Taffy usage metrics failed to start on bStats` or `... on FastStats`) and is skipped.

From `0.2.1`, one plugin per server reports the usage chart to each provider. The first plugin to start a provider's usage instance names itself in a system property, `taffy.usage.bstats` or `taffy.usage.faststats`, which every relocated copy of Taffy reads. A plugin that finds another plugin's name there starts no usage instance for that provider and logs nothing; its own metrics start as before. `shutdown()` of the plugin named there unsets the property, and no other plugin takes the chart over until it next starts its own metrics. A copy of Taffy older than `0.2.1` neither reads nor sets the properties, so a plugin built with one still starts the chart.

### Turning the chart off

From `0.2.1`, `usageChart(false)` on the builder leaves the chart off for that plugin alone. `start()` then starts no second bStats instance and no second FastStats context, and neither reads nor sets the two system properties, so another plugin on the server can still report the chart. The plugin's own bStats instance, FastStats context and error tracking start as before. The chart is on when the plugin does not call `usageChart`, as in `0.2.0`.

A plugin whose config lists every value it collects either names the `taffy_version` chart beside its metrics switch or gives the chart a key of its own:

```java
metrics = new MetricsBuilder(this, errors, settings.startup().metrics())
    .bStats(BSTATS_SERVICE_ID)
    .fastStats(FASTSTATS_TOKEN)
    .usageChart(settings.startup().metricsTaffyVersion())
    .start();
```

## Server owner switches

Every plugin on the server shares the two SDK configuration files. The plugin's own switch is separate and comes first: with it off, nothing starts.

| File | Key | Effect |
|---|---|---|
| `plugins/bStats/config.yml` | `enabled` | `false` turns bStats off. `start()` shuts the bStats instance down again at once and `bStatsStarted()` reads `false`. A file that cannot be read counts as on. |
| `plugins/faststats/config.properties` | `enabled` | `false` turns FastStats off for every plugin. `-Dfaststats.enabled=false` on the server command line does the same. |
| `plugins/faststats/config.properties` | `submitMetrics` | `false` stops metrics submissions. |
| `plugins/faststats/config.properties` | `submitErrors` | `false` stops error reports; `start()` then clears the error sink. |
| `plugins/faststats/config.properties` | `submitAdditionalMetrics` | `false` leaves every chart added with `addChart` out of the submissions. FastStats then sends only the fields it fills itself. |
| `plugins/faststats/config.properties` | `debug` | `true` logs each send through the plugin's logger. |

## Threads

- A started bStats instance runs on its own `bStats-Metrics` daemon thread while bStats is enabled. The Taffy usage chart adds a second one beside the plugin's own, in the plugin that reports it.
- FastStats runs its HTTP client with its tasks on Paper's async scheduler.
- The final FastStats send at `shutdown()` runs on a daemon thread named `taffy-metrics-final-send`, started for that send, and the disabling thread waits at most 5 seconds for it. Through `0.2.0` it ran on the disabling thread.

## Unit tests

A plugin passes `false` as the switch in its own unit tests. bStats refuses to start from classes that were not relocated, which they are not in a plugin's test run, and FastStats writes `plugins/faststats/config.properties` under whatever folder the mocked server gives. With the switch off, `start()` touches no SDK and returns an inert handle whose readers read `false` or `null`.

```java title="MetricsSetupTest.java"
import org.bukkit.plugin.Plugin;
import org.junit.jupiter.api.Test;
import so.alaz.taffy.metrics.MetricChart;
import so.alaz.taffy.metrics.Metrics;
import so.alaz.taffy.metrics.MetricsBuilder;
import so.alaz.taffy.platform.ErrorReports;

import static org.junit.jupiter.api.Assertions.assertFalse;
import static org.junit.jupiter.api.Assertions.assertNull;
import static org.junit.jupiter.api.Assertions.assertThrows;
import static org.mockito.Mockito.mock;

class MetricsSetupTest {

    @Test
    void switchOffStartsNothing() {
        Metrics metrics = new MetricsBuilder(mock(Plugin.class), new ErrorReports(), false)
            .bStats(12345)
            .fastStats("0123456789abcdef0123456789abcdef")
            .addChart(MetricChart.number("open_menus", () -> 0))
            .start();

        assertFalse(metrics.bStatsStarted());
        assertNull(metrics.fastStatsSdk());
        assertFalse(metrics.fastStatsErrorTracking());
        metrics.shutdown();
    }

    @Test
    void reservedIdIsRefused() {
        assertThrows(IllegalArgumentException.class, () -> MetricChart.number("player_count", () -> 0));
    }
}
```

The test uses JUnit and Mockito from the catalog. The Taffy Gradle plugins run tests on the JUnit Platform and pass the Mockito core jar on the test classpath to the test JVM as a Java agent:

```kotlin title="build.gradle.kts"
dependencies {
    testImplementation(alaz.junit.jupiter)
    testImplementation(alaz.mockito.core)
    testRuntimeOnly(alaz.junit.platform.launcher)
}
```

Chart ids are checked when the chart is declared, so a test that builds the plugin's charts catches a bad or reserved id without starting any provider.
